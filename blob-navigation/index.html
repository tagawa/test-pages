Blob URL Navigation Tests

Purpose: verify that blob: URL navigations intended for in-page rendering (not downloads) work correctly — payment/purchase flows, receipt pages, document viewers.

How results work: a blob document inherits the origin of the page that created it, so each generated blob can report back through localStorage and BroadcastChannel. A test that renders reports RENDERED by itself. A test that shows a blank page reports nothing and ends up as NO REPORT — that is the failure signal.

Related iOS fix: ddg-workflow PR #58
Read before filing a pass: groups A and B should all reach RENDERED. Group C is the opposite — those must download or preview and must not render as a blob page. Group D is a manual checklist that catches side effects the automated table cannot see.
